- Pickup motion tests: `python -B -m unittest discover -s bot-code/actions -p test_pickup.py -v` (NumPy required; fake bbos and virtual time, no hardware). Keep these separate from reasoning tests. Every `pickup.py` run first initializes each arm from its own `cfg.home`: 90-degree elbows, open claws, raised lift, then shoulder/wrist reset. This requires an already-homed, unloaded robot and is not encoder homing. Out-of-range home targets or failure to reach the reference pose abort pickup. The raised reference now offsets J4 from home by a mirrored quarter-turn (+0.25 left, -0.25 right, signed from the calibrated elbow pose), rolling the claw openings vertical; an unreachable roll or a target inside the stop margin aborts pickup. J6 then rotates inward from this repeatable raised/spread reference before lowering, preserving initialized J4 roll, J5 and open J7 claw setpoints, then squeezing, lifting back to shoulder level with that grasp preserved, and holding until termination by default. `--hook` caps the pre-descent J6 rotation (0 skips it), not a blended J5/J6 motion; `--squeeze` defaults to 0.03 J2 turns past contact; `--bottom-margin` defaults to 1.0 lift turns toward the top from the calibrated bottom, not a measured floor clearance (0.2 turns higher than the previous stop). After wrist preparation, J3 extends 30 degrees from its 90-degree home bend while raised, then holds that reach pose through descent, squeeze and the default final lift. `--elbow-extension` is in turns (default `30/360`, 0 disables); targets must remain between home and straight and inside calibrated stop margins. Both elbows must reach their targets before descent. `--lower-only` skips wrist preparation, grasping and the final lift, but still extends the elbows; `--pickup` adds grip and cradle before the shared final lift, without another wrist rotation. The final hold keeps publishing the shoulder-level and grasp setpoints with torque enabled until Ctrl+C (or an explicit `--hold` duration). Cradle flex is relative to the extended reach pose, not the old 90-degree reference. Exiting still disables torque and releases the box.
- Loaded pickup ascent uses the regular timed `ramp_joint` followed by `settle_joint`; feedback-based lift synchronization was removed at the user's request. `LIFT_SPEED` remains 0.4 turns/s. The final lift and shoulder-level grasp hold remain enabled by default, with the 30-degree elbow extension, wrist roll, bottom margin, squeeze and motor protections unchanged.
- Four-box demo: `uv run --offline bot-code/main.py --mock --planner deterministic`. Alternatively `python -S bot-code/main.py --mock` works without installed robot or model packages.
- Agent is the default CLI mode. `--mode oneshot` is the separate legacy fixed-grid pipeline, not a mobile fallback.
- Live integration uses `--provider module:factory` returning `agent_adapters.AgentProviders` and an explicit `--box-size` in meters. `FunctionActions` v2 callbacks receive the full `ActionRequest` (not just `Step`) and return `FunctionResult`, with possession/readiness supplied separately by `read_state`.
- The action/perception handoff is interface v2 in `bot-code/agent_types.py`, documented under "Agent component interface v2" in `bot-code/README.md`. It includes inline scene images, phase-aware monitoring, receipt lookup and load-preserving stop. `ActionOutcome.ts` is immutable terminal/transition time; `observed_at` is the heartbeat. Placement evidence must postdate terminal completion.
- Offline component mocks are `MockAgentWorld.actions` and `.observations`, sharing virtual time and injectable faults. Never combine live actions with mocked safety/possession evidence. Focused portable verification from `bot-code/tests`: `python -B -S -m unittest test_agent test_agent_adapters test_agent_backend.BackendTests test_agent_cli test_panel.PanelTests -v`.
- Provider status/state/observation/stop calls must have bounded latency. Provider cleanup closes observation/transport resources only; it must not implicitly release, park, or disable a loaded robot. A successful action does not by itself establish possession or placement.
- Action and perception implementations are independently owned. Do not import action test scripts from reasoning code or tests. Shared `contracts.py` and `WIRE_FORMAT.md` remain frozen.
- Mock mode does not contact the model even if OPENAI_API_KEY exists, unless `--allow-api-with-mock` is explicitly supplied. Do not run real hardware or paid API calls as part of normal verification.
- Main UI: export `OPENAI_API_KEY` in the launching terminal, then run `uv run --offline bot-code/main.py --ui`. It serves the panel on 127.0.0.1:8005 and receives EOF-framed Minecraft designs on TCP 5005. UI builds deliberately use real model decisions and simulated tools; nothing starts until the user clicks Start. `--ui-host`, `--ui-port`, `--receiver-host`, and `--receiver-port` are configurable.
- The shared panel key stays on the bot as `bracketbot` in `/home/bracketbot/.config/crafter/openai_api_key` (file mode `600`, newly created parent `700`). Save through `main.py --save-api-key` in the user's own terminal; it refuses overwrite. `OPENAI_API_KEY` takes precedence over the saved file. See README.md for hidden-input setup and SSH-forwarded developer access; developers do not need to retrieve the server key. GitHub Actions secret values cannot be downloaded for local use.
- The panel also accepts an API key through its masked Connect your model form. This sets a server-memory-only key for that panel process, requires CSRF protection and HTTPS or a loopback/forwarded connection, and is cleared on shutdown. Never request or log a real key in chat, test output, or repository files.
- The panel retains only the latest valid design, freezes the active build's design, and returns to main on cancellation. An in-flight model request may finish before a new build can start, but its late results cannot restart the cancelled build.
- Full UI verification without paid model calls: `uv run --offline --with fastapi --with uvicorn --with httpx --with openai --with quickjs==1.19.4 python -B -m unittest discover -s bot-code/tests -q`. QuickJS is an optional test-only syntax/projection checker, not a panel runtime dependency. Stdlib-only runs skip the optional web/JavaScript tests.
- Non-interactive SSH sessions do not put `uv` on PATH; use `/home/bracketbot/.local/bin/uv` for bot-side uv commands.

- Cloud recording import: `python3 import-recordings.py --list`, `--dataset CATEGORY/RUN` (repeatable), or `--all`; supply `BB_API_KEY` through the environment, never source code or CLI arguments. Uses `https://api.bracketbot.com`, Python 3.10+ stdlib and system `curl`; no robot access or cloud deletion.
- Imported recordings go to Git-ignored `recordings/` beside the script (override with `--output-dir`). Each processed episode becomes a collision-resistant JSON filename; existing files are skipped, not overwritten. JSON matches Mimic's single-line `name`, `saved_at`, `frames` format, with only `t`, `left`, `right` per frame.
- Importer reads `_derived/v1/episodes/*/analysis/sensors.json`, transposes only the eight-axis `arm_left_state.pos` / `arm_right_state.pos` arrays, and preserves their motor-turn values and episode-relative seconds. Frames merge both timestamp streams and hold each arm's latest sample once both exist, without interpolation or calibration normalization. Precision and sampling are limited to the cloud-derived JSON, not raw NPZ data.
- Importer offline verification: `python3 -B -m unittest discover -s bot-code/tests -p test_import_recordings.py -v`. Network calls are mocked; no real credentials or hardware are used.
